Key facts about the existing farmer app (from source):
  • Multi-farm is already built. Farms are created via the AddFarmModal opened from the navbar FarmSwitcher, and every intelligence screen re-fetches when you switch the active farm.
  • Location drives the data. Recommendations & Mandi Prices use a shared LocationBar — the active farm's location by default, overridable via dropdowns or a map pin. If a location has no forecast coverage the picker auto-opens.
  • Some screens are illustrative. Yield / Soil / Weather / dashboard sub-metrics are deterministically derived per-farm (no dedicated backend endpoints yet) — flagged in code comments, worth noting on the wireframe so nobody assumes they're live sensor data.
  • Add-farm fields: mandatory = name, state, district, size(acres); optional = soil, irrigation, crops. State/District are free-text today — converting them to dependent dropdowns is the obvious UX upgrade.

Admin (Govt)

Goal: see everything across all farmers/farms and act on aggregate, district-level recommendations.

Needs: a "list of everything" registry, high-level (aggregated) recommendations, and drill-down into any farm.

🟠 Not built yet. The current app has no role system — auth is a single farmer identity. Everything below is proposed. It reuses existing pieces (the recommendation engine, the farm data model, the shell) rather than inventing new ones.

Guest (Explore)

Goal: try YieldAI's recommendations for a region without signing up, then convert.

Needs: zero-friction preview, sample data, a clear signup nudge on any personalised action.

🟠 Not built yet. Today the root route forces unauthenticated visitors to /login — there is no public/guest entry point. Proposed below, reusing the existing Recommendations & LocationBar components.
